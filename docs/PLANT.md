# 工厂产线布局通道（Blender）

用 Blender 5.2 按参数原生生成一座车间，并在生成的几何上实测布局规则。AI 和工程师都只能提交参数；结论只来自原生测量和 EvalArc 对照。

## 生成什么

`native/blender_plant.py` 是受控配方，不接受用户 Python 或上传的 .blend。它按以下 7 个有界参数生成场景：

| 参数 | 范围 | 含义 |
|---|---|---|
| `stations` | 3–8 | CNC 工位数（每个工位：加工中心、六轴机器人、三面围栏、工件、检测相机） |
| `stationPitch` | 3.5–7 m | 工位节距 |
| `aisleWidth` | 1.2–4.5 m | AGV 通道设计宽度 |
| `guardSize` | 2.6–5 m | 机器人安全围栏边长 |
| `rackRows` | 1–4 | 托盘货架排数（4 层） |
| `cameraHeight` | 2.4–6.5 m | 检测相机龙门高度 |
| `agvs` | 0–4 | AGV 台数 |

场景还包括柱网、桁架、地面标线、输送线和滚筒、桥式起重机，以及高棚灯。生成分为 8 个阶段：厂房、输送线、CNC、机器人、围栏、货架、物流、检测。每个阶段导出一个 GLB，通过 SSE 推到视口。

- 机器人是关节层级（J1/J2/J3/J5），有取放关键帧。AGV、输送线上的纸箱和起重机也有关键帧。最终 `scene.glb` 带动画，视口可以播放。这些运动只用于演示，不是动力学或节拍仿真。
- 材质使用 Principled BSDF：金属、玻璃透射、程序化磨损和自发光。灯光为天空 + 太阳 + 面光。屋顶和外墙只出现在 .blend 和渲染里，这样交互视口可以看进车间。
- 候选用 Cycles 渲染 960×540 全景图和检测相机视角图，基准渲染预览图。

## 实测什么

全部检查都在第 1 帧的静态几何上进行，移动设备不参与。用 BVH 射线测量：

| 检查 | 方法 |
|---|---|
| `footprint-area` | 厂房外包络面积 ≤ 上限 |
| `aisle-clearance` | 沿通道取 41 个截面、每个截面 3 个高度，向两侧打射线，取最窄净宽 ≥ 下限 |
| `guard-clearance` | 从每个机器人基座水平打 36 条射线到围栏，所得距离减去声明的 1.45 m 机器人包络，最小值 ≥ 下限（不是关节极限可达性） |
| `camera-coverage` | 每个工位的检测相机射线首先命中本工位工件，且工件投影在视锥内 |
| `egress-travel` | 从任一工位沿通道到较近出口的直角路程 ≤ 上限 |

基准是 4 工位参考产线，每次评审都会重新生成和测量。参考产线和候选分别生成 JUnit，再由 EvalArc 对照，统计丢失的检查。

## 典型结果

6 工位、节距 4.5 m，围栏从 4.0 m 加大到 4.2 m，设计通道 2.4 m：
- 围栏间距 0.63 m，通过。
- 加大的围栏挤占了通道，实测净宽只有 2.08 m（要求 ≥ 2.4 m），结论为拒绝，EvalArc 报 1 项回归。
- 把设计通道加宽到 2.8 m 后，净宽 2.48 m，占地 641.6 m²（≤ 650 m²），全部通过。

见 `npm run test:plant`，以及工业用例 [P1/P2](INDUSTRIAL_TEST_CASES.md)。

## 使用

- 表单：候选设计 → “工厂产线”。表单会实时显示按配方估算的厂房尺寸。
- 对话：例如“设计 6 工位 CNC 产线：节距 4.5 m，围栏 4.2 m，通道 2.4 m…”。规则解析器会生成 `plant-layout` 计划。
- AI 引擎：在失败的检查上点“问 AI”。模型拿到实测值和工具说明（包括配方的几何关系），只能提出 `plant-layout` 计划，由你确认后执行。
- API：`POST /api/projects/:id/scenes`，请求体为 `{requestId, projectRevision, variant: "plant", layout, requirements}`。

## 范围

这是合成配方，不是实测工厂。不覆盖以下内容：动力学、关节极限、节拍或产能、照度、安全认证（如 ISO 13857 / ISO 10218）、消防规范校核，以及现场测量。
