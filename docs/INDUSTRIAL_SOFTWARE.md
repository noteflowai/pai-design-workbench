# 工业软件与 PAI 接入分析 · 2026-09-30

Blender 应当进入核心链路，但工程设计不能只依靠 Blender。统一工作台连接不同原生工具，保存各自可编辑文件与验证结果，才能覆盖专业设计任务。

本次查询官方功能、API、导出格式和公开 release 元数据；保存了请求状态、内容哈希和查询日期，见 [来源清单](research/industrial-sources.json) 与 [最新 release 快照](research/latest-releases.json)。可访问网页不等于已经获得软件授权或通过原生接口验证。

## 选择与边界

| 软件 | 最适合承担的环节 | 原生证据与验收重点 | 本仓库状态 |
|---|---|---|---|
| **Blender 5.2.2 LTS** | 工作单元布局、相机/视觉、资产、可视化与宣传制作 | `.blend`、GLB、实际射线/投影、尺寸、渲染；不能据此宣称 CAD/DFM 或动力学通过 | 已接入原生生成、检查、EvalArc 对照及反馈复测 |
| **FreeCAD 1.1.4** | 参数化机械 CAD、尺寸约束与装配 | 原始 `.FCStd` + STEP；约束、实体有效性、公差与装配干涉 | 下一优先级 |
| **CadQuery 2.8.0** | 易审计的程序化实体建模 | 参数化 `.py` + STEP/B-Rep；真实实体、体积、尺寸与孔位检查 | 下一优先级，与 FreeCAD 互补 |
| **OpenSCAD 2021.01 stable** | 配置化零件、CSG | `.scad`、网格；不能把 STL 检查当成完整工程实体检查 | 已调研，按任务采用；nightly 单独管理 |
| **SolveSpace 3.2** | 轻量几何约束、机构草图 | `.slvs`、原生约束与导出 | 已调研 |
| **Onshape** | 云端协作 CAD、FeatureScript、装配与版本 | 授权 API、不可变 document/version、原生模型与导出 | 接口规划，尚未连接账户 |
| **Autodesk Fusion / Inventor** | 机械设计及制造工作流 | 原生设计、SDK 与授权账户；产品页本次有访问限制 | 重要商业生态，接口待复核 |
| **SOLIDWORKS** | 专业机械 CAD 与既有企业工作流 | 原生部件/装配、授权工作站与自动化 | 2026 Web Help 可达；动态内容、SDK 与执行未验证 |
| **Siemens NX** | 集成 CAD/CAM、制造与企业工作流 | 原生模型、几何/工艺验证、授权环境 | 官方定位已复核，原生执行待接入 |
| **CATIA** | 复杂工程、系统与装配 | 官方页 R2026x；保留产品线和原生版本信息 | 已调研，需授权执行环境 |
| **PTC Creo** | 关联参数化模型、工程与制造 | 原生部件/装配与下游验证；不要只保存渲染 | 官方功能已复核 |
| **Rhino/Grasshopper Compute** | 曲面、计算设计与服务端几何 | `.3dm`/`.gh`、SDK/REST、实际几何验证 | 官方 REST 路径已复核，服务未连接 |
| **Gazebo Jetty LTS** | 机器人世界、传感器、动力学与 ROS | SDF/URDF、原生日志、控制与传感器检查 | 规划；需实际新实验 |
| **Isaac Sim** | USD 机器人场景与 GPU 仿真 | USD、原生版本、运行日志、策略/传感器验证 | 文档页面可达；版本与实际执行未复核 |

FreeCAD 官方说明原生参数化与装配能力。CadQuery 官方导出文档明确：只有原始 Python 保留其完整参数化信息，STEP 等交换格式不能替代它。Onshape 官方文档包含 OAuth/API key、限额、FeatureScript、装配与发布管理，因此集成需要版本与授权语义，而非简单 HTTP 调用。

NX/Creo/CATIA 的完整工程工作流提醒我们保留设计关联、装配和下游验证。厂商页面上的效率数字是厂商陈述，本仓库没有复测，也没有把这些数字作为自身效果。

## 当前实际接入

受控 Blender 脚本生成一个明确标注为**合成静态几何**的 4m × 3m 工作单元。模型包含机器人示意、工作台、目标、检查相机和可选遮挡物，输出可编辑 `.blend`、GLB、PNG 与原生 JSON 检查。

验收包括实际占地、声明的目标包络、Blender 射线与相机投影可见性。带遮挡的候选应失去相机可见性检查，EvalArc 独立检测回归。反馈修正时保持原几何约束，重新生成场景、重新检查，再绑定新回执关闭。另用独立脚本重新打开保存的 `.blend`，核对真实保存的对象、单位、面积和射线首个命中对象。

声明的静态包络不等于机器人关节可达性；示意机械臂不包含真实 URDF/关节模型。此案例不能证明真实工厂节拍、运动安全、公差、材料或制造可行性。

## 后续三类专业 PAI

1. **视觉/场景与机器人实验设计 Agent**：Blender + 实际仿真/记录；先验证相机布局、场景资产和失败案例。
2. **工程几何设计 Agent**：FreeCAD/CadQuery 起步，按用户已有工作流接 Onshape、Fusion、SOLIDWORKS、NX、CATIA、Creo；要求可编辑模型、真实约束和几何检查。
3. **制造/工作单元优化 Agent**：真实过程与设备参数 + 仿真/工艺软件；增加 DFM、干涉、节拍、容差和专业审查，不用合成场景代替测量。

三类共用任务/需求版本、控制器、证据回执、EvalArc 原生检查映射、Robot Reel 回放与推广反馈。原生工具适配器分别负责单位、坐标系、文件类型、软件版本与许可；不让语言模型自己宣布工具输出通过。

## 更新策略

本次使用最新稳定 Blender LTS 与 npm 版本；Node 使用最新 LTS，并在 CI 检查最新 Current。锁定经过验证的具体版本，更新时必须重新通过原生文件生成、重开、检查映射和浏览器测试。

`releases/latest` 不能盲信：Tauri monorepo 本次返回的是 **tauri-driver alpha**，不是桌面框架稳定版。OpenSCAD stable release 较旧也不代表可以把 nightly 当成稳定版。桌面壳真正实现时，应分别查核心、CLI、JS API 的稳定兼容版本。
